# Evaluation hygiene

Following the SafeVibe plan's reproducibility rules (and the
agentic-evaluation checklist it cites):

- **Pinned everything.** Prompt templates are versioned
  (`prompts.PROMPT_VERSION`); every prompt sent and every raw model
  completion is stored verbatim in `results/store.sqlite` and, for the
  published bundle, under `experiments/e2_test_backfill/llm_outputs/`.
- **Recorded generator.** The published results were generated by an AI
  assistant (recorded completions replayed through the `scripted`
  backend). Anyone can regenerate the downstream metrics exactly:
  `testwriter experiment --config ... --completions ...`. Anyone can
  *re-run generation* with a local open-weight model via
  `--backend ollama` (pinned model name + temperature 0.2 + seed 42) or
  a free hosted tier via `--backend openai` and compare.
- **Real numbers only.** Coverage comes from coverage.py; mutation
  scores come from actually executing every mutant against the suites.
  No number in README.md or the dashboard is hand-written.
- **Known limits (stated, not hidden):**
  - The mutation engine implements six standard operators and does not
    detect *equivalent* mutants; surviving-mutant counts therefore
    include some unkillable mutants, so scores are lower bounds.
    Cross-checking against mutmut/cosmic-ray is future work.
  - The sandbox is process isolation (rlimits + timeouts + temp dirs),
    not a container boundary.
  - E2 currently covers 3 real targets; the plan's full study is 10-20
    repos (expansion is future work; the selection protocol is
    documented in experiments/e2_test_backfill/candidates.md).
  - The baseline arm and the loop arm use recorded completions from the
    same generator session family; budgets (candidate counts) are
    published per arm in results.json.
- **Honest AI-assistance disclosure.** The tool, the recorded test
  suites and this documentation were built with AI assistance (Instinct
  "Lumi"), as the SafeVibe plan's writing-hygiene section requires.
